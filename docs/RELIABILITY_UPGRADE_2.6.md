# WVA 2.6 판정 신뢰성 보완 및 검증

작성일: 2026-11-04 · 기준 커밋: `a40ddbcb7592bb977ef1d015010316f94bcc104f`

## 적용 목적

이전 소스 검토에서 정상 응답을 취약점으로 확정하거나 미실행 작업을 완료로 표시하는 반례를 확인했다. 이번 변경은 발견 수를 늘리는 것보다 **관찰한 사실과 확정 결론을 일치시키는 것**에 목적이 있다. 이전 58점 평가는 당시 코드의 실무 준비도 평가이며 이번 수정만으로 운영 검증이 완료됐다고 표현하지 않는다.

| 권한·연계 경로 | 서로 다른 키·세션의 연결, 근거 없는 SYSTEM 권한이 가능 | 실제 아티팩트 값·대상·세션으로 연결. 미인증·잘못된 키 거부와 실제 키 응답 대조. 경로 깊이·횟수·탐색량 제한 |

| 사용자 설정 | 검사를 꺼도 켜지고 낮은 요청 상한이 증가함 | 선택한 설정과 상한 유지. 동의 생략 거부. 로컬 심화 모드는 격리 완료로 표시하지 않음 |
| 배포·검증 기록 | 이전 바이너리의 PASS와 해시가 남아 있었음 | 빌드 시 소스·exe manifest 생성, 새 빌드는 NOT_RUN. 현재 해시와 다른 검증은 STALE로 구분 |

## 지원 범위의 변화

기본 외부 대상 진단의 SQL 조건·브라우저 XSS·헤더·쿠키·CORS·정보 응답 검사는 유지한다. 새 서버 규칙 R16~R19의 기본 자동 탐색·확정 분기는 신뢰할 증거가 부족해 제거했다. **R16~R19는 명시한 로컬 실습 계약에서만 실행하며 계약이 없으면 NOT_RUN이다.** 외부 운영 사이트의 일반적인 LFI·명령어·SSRF·파일 업로드 탐지를 모두 제공한다고 주장하지 않는다.

로컬 심화 모드는 대상 환경이나 네트워크 격리를 자동 생성하지 않는다. 해당 모드의 URL은 루프백 주소로 제한한다. 브라우저 자체의 sandbox와 대상 환경의 격리는 별개다. 프로필에 명시한 기존 로컬 저장형 XSS·시간 기반 SQL 검사는 기존 전제를 유지한다.

미인증 자격증명 응답은 INFO_DISCLOSURE/CWE-200으로 분류하고 한국어 노출 범위 확인·응답 최소화·실제 키 회수·계정별 재검증 조치를 제공한다. 계정 소유권 위반을 실제 대조한 POLICY_OBJECT는 BOLA_IDOR/CWE-639로 유지한다. 분류 이름과 권고사항도 실제 확인 수준에 맞춘다.

참고 점수는 실제 발견 항목에 대한 기존 계산값이다. 검사를 끄면 그 검사는 선택한 필수 범위에서 제외되므로 해당 범위의 완료 등급이 나올 수 있다. 이것이 전체 사이트의 안전 등급이라는 의미는 아니다. 선택한 검사의 전제 부족·미확정·오류는 보류로 남는다.

## 테스트 환경과 기대 결과

실제 테스트는 `.venv`와 `tests/`에서 수행한다. 새 `tests/lab/system_target.py`는 pytest 임시 폴더의 파일 읽기, 허용된 echo/printf 명령, 실제 루프백 HTTP 요청, 업로드 내용 저장·조회·정리를 제공한다. 반사·거절·방어 경로도 함께 제공한다. 이 실습 서버는 임의 명령을 실행하지 않으며 정확히 제한한 표식 출력만 허용한다. 업로드 내용은 무해한 텍스트이며 스크립트로 실행하지 않는다.

| 순서 | 수행 내용 | 예상 결과 |
| --- | --- | --- |
| 1 | 전체 자동 회귀 | 정상·반례·부분 실패·인증·그래프·해시 검증 통과. 테스트 도중 소스가 바뀌면 결과 확정 거부 |
| 2 | 재빌드 및 manifest 확인 | 2.6.0 exe 생성. 빌드 직후 validation_status=NOT_RUN, 소스·exe 검증 VALID |
| 3 | 한글 경로의 exe만 복사 | 시작·자산·내장 데모·보고서·종료 등 27개 검증 통과 |

전체 명령은 로컬 소유 실습 환경을 사용하며 외부 운영 사이트를 진단하지 않는다. 브라우저 검증에는 Node·Playwright·설치된 Edge가 필요하고 경로가 다르면 WVA_NODE·WVA_BROWSER 환경변수로 지정한다. source/exe 대조 스크립트는 자신의 임시 실습 서버와 실행파일 프로세스를 종료한다.

### 화면에서 새 실습 규칙 확인

1. 별도 PowerShell에서 `powershell -ExecutionPolicy Bypass -File .\tests\Start-SystemLab.ps1`을 실행한다.
2. WVA에서 `http://127.0.0.1:18914/`를 입력하고 **같은 서버 전체**, **로컬 심화 모드**를 선택한다.
3. **검사 선택·프로필**에서 `tests/benchmarks/profiles/system-loopback.json`을 선택한다. 이 예시는 Windows용이며 명령어 출력 방식이 windows로 지정돼 있다.
4. 이 표식 서버만 검사하려면 SQL·브라우저 체크를 끈다. 해당 선택은 파일의 같은 설정보다 우선한다. 요청 상한은 450이면 충분하다.
5. 점검 권한에 명시적으로 동의하고 시작한다. 파일·명령어·SSRF·업로드 각각 취약 경로에서 1개씩 총 4개가 발견되고, 방어·반사·거절 경로에는 해당 발견이 없어야 한다.
6. R14는 실제 업로드 정리·부재 확인에 근거해 PASS여야 한다. SYSTEM 권한이나 수집된 클라우드 키가 표시되면 실패다.
7. 완료 후 실습 서버 터미널에서 Ctrl+C로 종료한다. `tests/artifacts/system-lab`의 파일은 공개된 무해한 실습 파일이다.

## 남은 한계와 추가 업그레이드

- R16~R19는 명시한 로컬 계약 검사다. 실제 운영 사이트의 다양한 입력 문맥·파일 저장소·프록시·인증 구조를 일반화한 탐지기는 별도 설계와 독립 검증이 필요하다.
- 정상 반례와 소유 실습의 통과는 모든 사이트의 탐지 정확도나 오탐률을 뜻하지 않는다. 새로운 반례를 회귀 테스트에 추가하며 판정 기준을 보수적으로 유지해야 한다.
- 브라우저 XSS의 입력 위치·대기 시간·페이로드 문맥, 일반 SQL 조건의 응답 의미에는 한계가 있다. 미확정 상태를 강제로 확정으로 올리지 않는다.
- 요청 예산 소진·대상 장애로 정리가 실패할 수 있다. 이 경우 ERROR와 잔존 미확인을 기록한다. 모든 외부 저장소의 원자적 롤백을 보증하지 않는다.
- 연계 경로는 실제 관찰된 응답 접근의 연결이다. 임의 명령 실행의 최고 권한·관리자 기능 수행·서버 장악을 보증하지 않는다.
- Windows 한 대에서의 검증이다. 별도 Windows 11·백신 제품·인증서 서명·조직의 IdP·MFA·SSO·운영 DB 검증은 별개다.
- CI·배포 서명·GitHub Release 자산 관리·운영 이력 저장소와 다중 운영자 기능은 이번 변경에 포함하지 않았다. manifest와 검증 결과를 기반으로 다음 배포 자동화에 연결할 수 있다.
