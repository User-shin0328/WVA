# WVA 2.7 실행 규칙과 검사 프로필

2026-11-06. SQLi·XSS, 세션·CSRF·JavaScript 탐색, 검사 상태·등급 문제를 보완한 구현이며 2.7의 대표 SQL 후보와 중요 정보 노출 검사를 포함한다. [규칙 설계 전체](RULE_DESIGN.md)의 모든 세부 항목이나 모든 OWASP 항목을 구현했다는 의미는 아니다.

| R09 | 계정 간 객체 대조 | 명시한 소유자의 안정적인 비공개 필드와 거부 대상 계정·미인증 응답을 대조 |

| R11-T | 시간 기반 SQL 조건 | 명시한 로컬 시나리오만 3쌍 대조. 기대 지연 0.2~0.75초, 기준 지터와 일관된 차이 확인 |
| R12-S | 저장형 XSS | 명시한 로컬 저장 → 별도 브라우저 조회 → 고유 표식 실행 확인 → 소유 테스트 기록 정리 및 잔존 확인 |

HTTP 500이나 DB 오류 문자열 한 번으로 SQLi를 확정하지 않는다. DB 오류만 있으면 SIGNAL, 기준 불안정은 SIGNAL, WAF·인증·통신 문제는 오류·미실행으로 구분한다. SQL 기본 규칙은 DB 쓰기·다른 테이블 추출·시간 지연을 하지 않는다. 시간 기반 검사는 별도 선언을 요구한다.

XSS는 안전 인코딩과 CSP 차단을 실제 실행 확인과 구분한다. 쿠키 읽기·외부 전송·실사용 계정 작업은 하지 않는다. 고유 표식은 실행 증거이며 피해 규모나 모든 입력 문맥을 입증하지 않는다. 기존 `surface/reflection.py`는 별도 레거시 도우미로 보존하며 새 R06은 `agents/injection_auditor.py`를 통해 실행한다.

## 요청·브라우저 경계

- 기본 450회, 설정 가능 범위 40~1,000회. 같은 예산을 세션·브라우저·확장 검사도 공유한다. 요청 간 최소 25ms 간격이다.
- 응답 스트림 기본 5,000,000 bytes, 최대 설정 10,000,000 bytes. `Accept-Encoding: identity`를 사용하며 서버가 다른 압축 응답을 강제하면 오류로 중단한다.
- 스킴·호스트·포트와 선택한 경로 경계를 모든 요청에 적용한다. 기본 GET·HEAD만 허용한다. 로그인 또는 로컬 저장·정리 프로필에 **명시한 정확한 URL**에만 POST를 추가 허용한다.
- 리다이렉트를 HTTP 클라이언트에서 자동 추적하지 않는다. 브라우저의 다음 요청도 같은 경계에서 다시 검사한다. WebSocket·Service Worker·다운로드를 차단한다.
- 브라우저 HTTP를 직접 통과시키지 않고 공통 제한 HTTP 클라이언트로 전달한다. 종료 시 네트워크를 먼저 오프라인으로 바꾸고 요청 콜백과 브라우저 컨텍스트를 정리한다.
- 브라우저는 개인 프로필을 사용하지 않는다. 설치된 Edge·Chrome을 찾고 없으면 Playwright Chromium을 확인한다. 사용할 브라우저가 없으면 NOT_RUN이다. 별도 Python 설치가 없는 exe에도 Playwright 실행 드라이버를 포함한다.

## 상태와 참고 등급

| 상태 | 의미 |
| --- | --- |
| PASS | 실제 검사한 후보에서 해당 조건을 확인하지 못함. 전체 사이트 안전 보증 아님 |
| FINDING | 반복 조건 또는 실행 표식 등 규칙의 발견 조건 충족 |
| SIGNAL | 반사·DB 오류·불안정 등 검토할 신호. 취약점 확정과 구분 |
| NOT_RUN | 후보·브라우저·계정·정책·시나리오 부재 또는 사용자가 끔 |
| ERROR | 통신·권한·WAF·요청 예산·정리 실패 등으로 검사가 완료되지 않음 |
| NOT_SUPPORTED | 아직 지원하지 않는 검사. PASS로 변환하지 않음 |

화면의 **검사 선택·프로필**, **검사별 수행 상태**, 자동 JSON/Markdown, 선택 저장의 metadata에 같은 상태를 제공한다. `required`는 사용자가 선택하거나 시나리오를 지정한 검사다. 필수 검사의 미실행·미확정·결과 누락 또는 어느 검사의 오류가 있으면 종합 판정은 **보류**한다. 2.7에서는 완료 후 **발견 기준 참고 등급**을 별도 표시하고, 미완료 항목을 함께 표시한다. 발견과 일부 미확정이 함께 있는 경우에도 `inconclusive` 수를 기록한다. 작업·검사 0회를 PASS로 만들지 않는다. 숫자 점수는 발견 건수의 참고 수치이며 안전 인증이 아니다. 비교 이력에도 동일 기준을 적용한다.

## 일반 프로필과 세션

화면에서 SQL 조건 대조와 브라우저 검사를 켜고, 필요한 매개변수를 쉼표로 지정한다. 2.7에서는 발견한 GET 매개변수를 우선하며 대표 후보 `id`, `user_id`, `product_id`, `q`, `search`, `keyword`를 실제 시작 엔드포인트에서 추가 확인한다. 후보 한도 기본 12개, 설정 1~24개다. 추정 후보는 두 정상 값에 반응이 있는지 먼저 확인하고, 전부 반응이 없으면 NOT_RUN이다. 일반 언어·태그 필드는 자동 변형에서 제외하며 필요하면 명시한다. 입력에 관계없는 중복 쿼리와 언어 값은 유지한다.

2.7 추가 규칙: R21 `.env` 비밀 필드, R22 `.git/HEAD` 및 `.git/config`, R23 `/actuator/env` 비마스킹 비밀 필드를 미인증·반복·무관 경로 대조로 검사한다. [세부 판정 근거와 제한](WORKFLOW_UPGRADE_2.7.md)을 따른다.

검사 프로필은 JSON 파일로 선택한다. 파일을 서버 폴더로 복사하거나 브라우저 저장소에 저장하지 않는다. 이번 진단의 메모리에만 유지한다. SQL·브라우저 체크박스는 JSON의 동일 설정보다 우선한다.

```json
{
  "parameters": ["id", "q"],
  "primary_session": "A",
  "sessions": [
    {
      "alias": "A",
      "login_url": "http://127.0.0.1:18913/login",
      "login_fields": {"username": "A", "password": "local-only-A"}
    },
    {
      "alias": "B",
      "headers": {"Authorization": "Bearer LOCAL_TEST_TOKEN"}
    }
  ],
  "access_cases": [
    {
      "url": "http://127.0.0.1:18913/object/vulnerable",
      "owner": "A",
      "denied": ["B", "anonymous"],
      "protected_fields": ["private_record"],
      "kind": "object"
    }
  ]
}
```

위 값은 별도 실습 앱 전용 예시다. 실제 계정 정보를 저장소에 커밋하지 않는다. `primary_session`을 지정하면 일반 탐색·SQL·브라우저 검사도 해당 세션을 사용한다. 다른 계정의 정책 대조는 격리된 쿠키 저장소를 사용한다. 기준 세션을 지정하지 않으면 일반 검사는 미인증으로 수행한다.

로그인은 제공한 폼 필드와 숨겨진 CSRF 값을 같은 쿠키 저장소에서 제출한다. GET 검사도 매번 숨겨진 CSRF 값을 갱신한다. 별칭·보호 정책이 없으면 계정 권한을 임의로 추측하지 않는다. `anonymous`는 별도 미인증 저장소다. `kind: role`과 관리자 소유자 별칭을 사용하면 역할 대조를 수행한다. `protected_fields`는 JSON의 `object.private_value` 같은 중첩 키도 지원한다.

로그인·정책 URL이 입력 경로 밖에 있으면 경계에서 차단되므로 필요한 경우 사용자가 **같은 서버 전체**를 선택해야 한다. MFA·CAPTCHA·SSO와 임의 JSON 로그인 절차를 자동 해결하지 않는다. 이미 확보한 테스트 쿠키 또는 Authorization/X-API-Key도 프로필로 제공할 수 있다.

## 저장형·시간 기반 로컬 검사

완전한 재실행 예시는 [advanced-loopback.json](../tests/benchmarks/profiles/advanced-loopback.json)에 있다. 이 프로필은 **본인 PC의 전용 실습 앱**을 위한 것이며 운영 사이트용 기본 프로필이 아니다.

```powershell
# 별도 PowerShell에서 로컬 실습 앱 시작
.\.venv\Scripts\python.exe -m tests.lab.advanced_target --port 18913
```

WVA에 `http://127.0.0.1:18913/`과 같은 서버 전체 범위를 선택하고 예시 프로필을 읽는다. 이 앱의 계정 암호는 공개된 실습용 값이다. 검사 후 터미널의 Ctrl+C로 종료한다.

저장형은 `write_url`, `read_url`, `cleanup_url`, 입력 `field`, 소유 기록을 지정하는 `fields`가 모두 필요하다. 생성한 `wva_marker`를 정리 요청에도 전달한다. 브라우저가 준비되기 전에는 저장하지 않는다. 취소·오류 경로에서도 정리하고 표식 잔존을 확인한다. 정리 오류는 상태 사유에 남기므로 사용자가 전용 기록을 확인해야 한다.

시간 기반은 `url`, `parameter`, `true_value`, `false_value`, 기대 `delay`가 필요하다. 자동으로 임의 DB 문법을 추정하거나 운영 대상에 지연을 주지 않는다. 예시 앱은 실제 SQLite 쿼리와 제한된 지연 함수를 사용한다. 양쪽 값을 같은 3쌍으로 반복해 지터를 확인한다.

자동 source/exe 대조와 임시 환경 정리를 한 번에 수행할 수 있다.

```powershell
.\.venv\Scripts\python.exe -X utf8 -m tests.benchmarks.extended
```

예상 결과는 계정·역할·시간 SQL·저장형 XSS와 정리, source/exe 일치, 비밀 값 가림의 **10개 검증 PASS**다. 실제 결과는 `tests/artifacts/benchmark/extended-result.json` 및 테스트 결과보고서에 기록한다.

## 2.6 서버 규칙의 로컬 계약

R16~R19는 `system_cases`에 명시한 로컬 심화 시나리오만 수행한다. 파일 규칙은 알려진 무해한 파일의 표식, 명령 규칙은 입력 원문에 없는 분리된 고유 출력, SSRF는 별도 수신 기록의 횟수, 업로드는 성공·내용 조회·정리 후 부재를 확인한다. 원격 일반 사이트의 자동 검사로 확대하지 않는다. 표식 출력이나 파일 저장만으로 SYSTEM 권한을 부여하지 않는다.

- 공통: `kind`, `url`, 필요한 `parameter`.
- `kind: file`: `control_value`, `probe_value`, `expected_marker`(16자 이상).
- `kind: command`: `shell`은 `windows` 또는 `posix`. 무해한 출력 템플릿만 사용.
- `kind: ssrf`: `{marker}`가 포함된 `callback_url`, `receipt_url`. 기록 응답은 해당 marker와 정수 count이며 정상 대조에서 0, 표식 전달 뒤 1이어야 함.
- `kind: upload`: `{filename}`가 포함된 `read_url`, `cleanup_url`, 선택적 업로드 `field`. 저장 응답 success=true, 별도 고유 내용 조회 2회, 정리 후 404가 필요함. 거절 응답은 확정 발견으로 세지 않음.

프로필당 최대 8개 시나리오다. 같은 서버·경로 경계를 유지하고 쓰기·정리 URL을 정확히 지정한다. 저장·업로드가 있으면 정리 확인을 끌 수 없다. [수동 실습과 source/exe 검증 절차](RELIABILITY_UPGRADE_2.6.md)를 따른다.

## 증거와 비밀 값 처리

위험 설명과 순서별 조치는 SQLi·XSS·정책 기반 계정·역할 발견 유형에 맞춰 제공한다. 실제 관찰과 가능한 공격·미확인 범위를 구분한다. 테스트 계정의 비밀번호·인증 헤더와 수집된 비밀 값은 보고서·이벤트·선택 저장에서 가린다. 잘못된 프로필의 검증 오류 응답에도 원래 입력값을 그대로 돌려주지 않는다. 내부 연계 검사는 메모리의 실제 값을 사용하며 공개 출력과 분리한다.

R11/R12의 현재 문법·출력 문맥·브라우저 대기 시간과 명시한 계정 정책에는 한계가 있다. 결과 0건은 후보 부재·인증 실패·미지원과 구분해서 해석하고, 실제 운영 사이트나 모든 브라우저·OS에서 검증됐다고 확대하지 않는다.
