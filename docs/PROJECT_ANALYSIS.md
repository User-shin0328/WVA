# WVA 폴더 분석 및 변경 내역

## 원래 구성

Python 분석 엔진(`agents/engine.py`)이 고정 경로와 HTML 링크·폼을 수집하고, 헤더·디버그 정보·BOLA·수집 키의 관리자 응답 접근을 검사합니다. `core/graph/attack_graph.py`는 수집된 전제 조건과 산출물을 연결하여 NetworkX 경로를 추론합니다. 기존 파일 이름의 Multi-Agent는 프로그램 내부의 고정 단계 모듈을 뜻하며 외부 LLM 호출 구현은 확인되지 않았습니다.

`surface/reflection.py`는 존재하지만 기본 엔진 흐름에서 호출하지 않습니다. 본 대시보드가 반사 취약점·XSS·SQL 주입을 검증한다고 표시하지 않습니다. JSON은 WVA 자체 스키마이며 SARIF 호환 형식이 아닙니다.

시작 시 `.exe`나 기존 PyInstaller 패키지는 없었습니다. 한국어/영문 배치 실행기 6개가 중복으로 있었습니다. 분석 코드와 기존 보고서는 유지하고 이 배치 파일만 삭제했습니다.

## 구현한 내용

- 단일 Windows 실행파일과 자동 브라우저 열기, 동일 서버 재사용, 포트 탐색, 앱 종료.
- 직접 대상 입력을 기본으로 하는 한국어 대시보드. 외부 CDN 대신 한글·숫자 폰트를 포함한 로컬 자산 사용.
- 발견 항목 검색·위험도 필터, 증거 펼치기, 3단계 연계 경로와 대응 증거 연결, 엔드포인트·로그 조회.
- 완료 진단의 Markdown/JSON 다운로드 및 고유 ID로 자동 저장. 중단·실패 결과는 완료 보고서로 내보내지 않음.
- 인프로세스 데모 서버로 변경하여 frozen 실행 중 자기 실행파일을 Python처럼 다시 실행하는 문제 제거.
- 진단 시작 시 상태를 먼저 예약하여 중복 실행 차단, 이전 결과 초기화, 종료 시 소유 테스트 서버와 작업 정리.
- 이벤트를 단일 소비 큐 대신 구독자별 커서로 제공. 최근 1,000개 이벤트와 재전송 지원. 화면은 1초 주기의 상태 조회로 갱신.
- 요청 전 정확한 출처·포트·스킴·읽기 메서드·위험 경로 확인, 리다이렉트 자동 추적 해제, TLS 인증서 검증 활성화.
- 단순 export 상태의 BOLA 오탐 제거, 관리자 응답의 privilege 필드 확인, CORS 인증 조건 및 쿠키 HttpOnly 대소문자 처리 보완.
- 연결 실패를 오류 상태로 처리하고 원인 안내. 활동 로그에서는 수집 키 값을 가림.
- 취약/방어 프로필과 기능·브라우저·단독 실행 검증, 한 문서에 순서·예상 결과·실제 결과 통합.

## 2.1 화면 개편

- 공통 소개 문구·지표 부가 설명·우선 조치 패널 제거. 완료 시 위험도와 CVSS 구간의 실제 건수 차트 표시.
- 현재 단계 로그 기반의 진행 모션과 완료 체크. 모션 감소 설정 지원.
- 75% 크기의 공통 상세 창에 위험도·증거·영향 범위·세부 조치·수정 후 확인 표시. 경로 단계에서도 화면 이동 없이 사용.
- 전체 폭의 발견 항목 표에 CWE·메서드·증거·조치 요약 추가. 경로 화면은 대상 → 경로 → 관련 발견 항목 순서.
- HTTP 상태·콘텐츠 유형·응답 시간·크기·시각·선택된 응답 헤더 수집. 링크·폼·API 문서의 출처와 매개변수 병합. 문서에 선언된 작업은 실행하지 않음.
- 진단마다 고유 JSONL 로그 파일에 상태와 활동을 기록하고 로그 화면에 실제 위치 표시.
- 요약·발견 항목·경로·표면·전체 파일 로그를 선택하여 JSON·Markdown·UTF-8 BOM CSV로 내보내기. 이전 진단 ID·미완료 결과·빈 선택 차단.

## 2026-11-01 권고사항 정리

항목별 조치를 실제 수행 순서의 번호 목록으로 정리했습니다. 각 단계는 순서·제목·조치·완료 기준을 포함하고 별도의 재검증 조건을 제공합니다. CSP와 HSTS는 각각의 절차만 표시합니다. 상세 창·선택 내보내기·자동 Markdown/JSON 보고서가 같은 단계 데이터를 사용합니다. 이는 권고 절차의 정리이며 대상 시스템의 설정을 자동 변경하는 기능은 아닙니다.

## 범위와 한계

정해진 경로와 응답 휴리스틱을 검사하는 로컬 참고 도구입니다. 로그인 세션 간 객체 소유권 대조, 전체 사이트 크롤링, 일반화된 API 권한 검증, 모든 웹 취약점, 최소 컷 최적화 알고리즘은 구현 범위가 아닙니다. 차단점은 경로의 각 단계에 대한 수정 후보이며 최소 비용을 수학적으로 최적화한 결과가 아닙니다. 연계 그래프는 아티팩트 유형을 기반으로 연결하므로 실제 시스템에서는 각 값의 출처와 권한 조건을 사람이 재검토해야 합니다.

테스트의 5건/1개 경로는 제공한 취약 실습 대상에서 관찰한 결과입니다. 외부 운영 환경의 검증 결과로 해석하지 않습니다. 자세한 증거와 미실행 항목은 `tests/TEST_GUIDE.md`를 참고하세요.
