# WVA · 웹 취약점 진단

Windows 실행파일과 로컬 브라우저로 사용하는 웹 진단 도구입니다. **직접 입력한 대상 진단 → 증거 확인 → 연계 경로 검토 → 보고서 저장**을 기본 흐름으로 제공합니다.

![WVA 진단 화면](docs/images/dashboard.png)

화면은 제공된 로컬 실습 대상을 진단한 결과입니다. 현재 검증된 Windows 실행파일 `WVA.exe`를 저장소에 포함하며, 빌드 해시와 테스트 기록은 `docs/BUILD_INFO.json` 및 `tests/TEST_GUIDE.md`에서 확인할 수 있습니다.

## 바로 실행

1. 이 폴더의 **`WVA.exe`**를 더블클릭합니다. Python을 따로 설치할 필요가 없습니다.
2. 브라우저에서 진단할 URL을 입력합니다. 서버 주소뿐 아니라 `https://example.com/app/?page=1`처럼 경로와 쿼리를 포함할 수 있습니다. **입력 경로와 하위 경로** 또는 **같은 서버 전체**에서 진단 범위를 선택합니다.
3. 진단 권한을 확인하고 **진단 시작**을 누릅니다. 진행 모션 후 완료되면 위험도·CVSS 차트와 상세 표가 표시됩니다. 발견 항목을 누르면 큰 상세 창에서 증거와 조치 절차를 확인합니다.
4. **경로 / 표면 / 로그** 메뉴에서 관련 정보를 확인합니다.
5. **저장** 화면에서 원하는 정보와 **JSON / Markdown / CSV** 형식을 선택해 내려받습니다.
6. **앱 종료**로 서비스를 종료합니다. 브라우저 탭만 닫으면 서버는 계속 실행됩니다.

기본 주소는 `http://127.0.0.1:9030`입니다. 포트가 사용 중이면 9031~9039 중 가능한 포트로 열립니다. 이미 실행 중인 WVA가 있으면 해당 화면을 재사용합니다. 포트를 지정할 수도 있습니다.

```powershell
.\WVA.exe --port 9040
```

새 실행파일은 대시보드, 한글/숫자 폰트, 로컬 데모를 포함합니다. 외부 CDN 없이 동작합니다. 어두운 배경·흰 글씨·청록색 선을 사용하고 직접 진단을 기본 작업으로 구성했습니다. 이전 배치 실행기 6개는 삭제했습니다.

## 2.6 판정 신뢰성 보완

성공 설명 문구·입력 반사·업로드 거절을 취약점으로 확정하던 분기를 제거했습니다. 계정 간 권한 위반은 선언한 정책으로 대조하며, 별도 미인증 요청의 자격증명 응답 노출과 구분합니다. 실제 정리·부재 확인 없이 PASS를 만들지 않고, 선택한 필수 검사에 미실행·오류·미확정이 있으면 참고 등급을 보류합니다.

경로 순회·명령어·SSRF·업로드(R16~R19)는 **명시한 로컬 실습 프로필의 독립 증거**가 있어야 검사합니다. 프로필이 없으면 NOT_RUN이며 외부 사이트에 대한 해당 네 규칙의 자동 확정 검사를 제공하지 않습니다. 로컬 심화 모드는 환경 격리를 자동 생성하지 않습니다. [변경 이유·검증·제한](docs/RELIABILITY_UPGRADE_2.6.md)을 확인하세요.

빌드 시 현재 소스와 실행파일 해시를 자동 기록하며 새 빌드는 검증 전 NOT_RUN입니다. `packaging/build_manifest.py --verify`로 소스·실행파일 정합성을 확인합니다.

## 기본 진단 규칙과 검사 상태

SQL Injection 조건 반복 대조와 반사형·DOM XSS 실행 확인을 엔진에 연결했습니다. `#/search?q=...` 같은 JavaScript 라우트도 입력할 수 있습니다. 쿠키·CSRF 세션을 유지하고, 브라우저 하위 요청에도 같은 출처·경로·메서드·횟수·응답 크기 제한을 적용합니다. Edge·Chrome 또는 Playwright Chromium이 필요하며 사용할 브라우저가 없으면 해당 검사를 미실행으로 표시합니다.

**검사 선택·프로필**에서 SQL·브라우저·요청 상한·매개변수와 계정/실습 프로필을 선택합니다. **검사별 수행 상태**는 실제 실행·발견·보류·미실행·오류를 구분합니다. 선택한 필수 검사가 미완료이거나 어느 검사든 오류가 있으면 참고 등급을 보류합니다. 숫자 점수는 발견 기준이며 안전 인증이 아닙니다. 계정·역할 대조, 저장형 XSS와 시간 기반 SQL은 명시한 프로필과 검사 전제가 필요합니다.

- [실행 규칙·프로필·요청 경계](docs/ACTIVE_RULES.md)
- [2.5 구현·검증 보고서](docs/IMPLEMENTATION_REPORT_2.5.md)
- [제3자 앱 결과와 이전 버전 비교](tests/benchmarks/RESULTS.md)

## 2.4 통합 기능

GitHub `428d272`의 JavaScript 자격증명 패턴 탐지, TLS 인증서 만료 임박 점검, 진단 참고 등급, 재진단 비교, 권한 확인과 로컬 2.3 상세 설명을 통합했습니다. AI 수정 프롬프트는 상세 창에서 접어 두고 필요할 때 복사합니다. 외부 AI 서비스로 자동 전송하지 않습니다.

등급은 발견 건수별 가중치로 계산한 참고 수치이며 완료된 진단에만 표시합니다. 재진단 비교는 대상 URL·진단 범위·규칙 버전이 같은 완료 보고서를 사용합니다. ‘이번에 미발견’은 조치 완료의 증명이 아니며, 이전 버전 보고서는 범위 메타데이터가 없어 비교에서 제외합니다. [통합 및 빌드 검증 기록](docs/INTEGRATION_REPORT.md)을 확인하세요.

## 테스트

공통 상세 창은 **문제 요약 → 확인한 내용 → 가능한 공격과 성립 조건 → 판정 범위 → 조치 순서 → 수정 후 확인** 순서입니다. 영어 원문 증거와 기술 정보는 접어서 제공하며, 조치는 첫 단계부터 펼쳐 읽거나 한 번에 모두 열 수 있습니다. 공격 설명은 실제로 확인한 동작과 구분하며 저장 보고서에도 포함합니다. CSV는 공격·성립 조건·판정 범위 열을 포함한 25열입니다. 추가할 13개 진단 규칙의 조건·오탐 방지·증거·시험 기준과 순서는 [규칙 설계](docs/RULE_DESIGN.md)에 정리했습니다. R06·R09·R10·R11·R12의 현재 실행 전제와 제한은 [실행 규칙](docs/ACTIVE_RULES.md)에 정리했습니다. 나머지 추가 설계 전체를 구현한 것은 아닙니다. 2.4 통합으로 R04와 일부 겹치는 JavaScript 자격증명 패턴 탐지와 별도의 TLS 인증서 만료 임박 점검이 추가됐으며, R04 전체 구현을 뜻하지 않습니다.

테스트 환경 `.venv/`와 `tests/`가 구성되어 있습니다. 상세한 실행 순서, 기대 수치, 판정 기준, 실제 결과보고서는 **[테스트 상세 설명](tests/TEST_GUIDE.md)** 한 파일에서 볼 수 있습니다.

```powershell
# 다른 PC에서 환경을 구축할 때
powershell -ExecutionPolicy Bypass -File .\tests\Setup-TestEnvironment.ps1

# 자동 기능 테스트 및 결과보고서 갱신
.\.venv\Scripts\python.exe -m tests.run_tests

# 직접 입력할 로컬 취약 대상: 별도 창에서 실행
.\.venv\Scripts\python.exe -m tests.lab.target --mode vulnerable --port 8990

# 방어 설정을 적용한 비교 대상: 다른 창에서 실행
.\.venv\Scripts\python.exe -m tests.lab.target --mode hardened --port 8991
```

제공된 취약 대상의 예상 결과는 엔드포인트 8개, 발견 항목 5개, 3단계 연계 경로 1개입니다. 방어 프로필은 엔드포인트 4개, 발견 항목과 연계 경로 0개입니다. 수동 대상은 테스트 후 `Ctrl+C`로 종료합니다. 화면의 **로컬 데모 실행**은 임시 포트의 실습 대상을 자동으로 시작하고 정리합니다.

DVWA·Juice Shop을 별도 설치한 [독립 취약 웹앱 검증](tests/benchmarks/README.md)도 제공합니다. 실제 SQLi·반사 XSS·DOM XSS와 방어 대조를 확인한 뒤 WVA 소스/실행파일의 결과를 비교합니다. 2.5부터 R11 SQL 조건 대조와 R12 브라우저 XSS를 실제 실행하며, 안전 인코딩·CSP·불안정 응답·WAF를 구분합니다. [실측 결과](tests/benchmarks/RESULTS.md)에 이전 미지원과 현재 탐지·방어 대조를 구분했습니다.

## 저장 위치와 오류 확인

- 완료 보고서: exe 옆 `reports/날짜_시간_진단ID.md` 및 `.json`.
- 진단별 활동 로그: exe 옆 `logs/scans/날짜_시간_진단ID.jsonl` (실시간 추가 기록).
- 실행 오류 로그: exe 옆 `logs/WVA.log`. 두 위치는 **로그** 화면에서 확인합니다.
- 해당 위치에 쓰기 권한이 없으면 `%LOCALAPPDATA%/WVA/` 아래를 사용합니다.
- 진단 실패·중단은 완료와 구분하고 완료 보고서 다운로드를 막습니다.
- 앱 재실행 시 화면 데이터는 초기화되며, 저장된 파일은 남습니다.

2.1 화면 구성: 진단 화면의 공통 설명 멘트·우선 조치 패널을 없앴습니다. 차트 아래 표에는 위험도·CWE·메서드·CVSS·증거·조치 요약이 표시됩니다. 경로 단계와 발견 항목은 같은 상세 창을 사용하며 현재 화면을 유지합니다. 표면 화면은 실제 응답 코드·시간·크기·헤더와 문서의 매개변수 정보를 구분해 표시합니다. 저장 화면은 요약·발견 항목·경로·표면·로그를 독립적으로 선택할 수 있습니다.

권고사항은 항목별 **조치 순서**로 정리합니다. 각 단계에 제목·실행할 조치·완료 기준이 있으며, 실제 순서는 문제 유형에 따라 다릅니다. 예를 들어 유출 키로 관리자 응답에 접근한 항목은 현황 확인 → 유출 키·접근 차단 → 관리자 권한 검사 → 새 인증 정보 발급 → 상위 노출 경로 정리 → 재검증 순서입니다. 상세 창, 선택 저장(JSON·Markdown·CSV), 자동 보고서에 같은 순서를 제공합니다.

`[Errno 42] Illegal byte sequence`가 발생한 초기 빌드는 교체했습니다. Python 런타임이 요구하는 TLS 인증서 정책 파일을 포함하고, 한글 경로에서 exe만 복사한 독립 실행을 검증합니다. 자세한 실제 결과는 테스트 문서에 기록됩니다.

## 분석 범위

2.2에서는 입력 경로·쿼리를 보존하고 HTML 상대 링크를 최대 80개 URL까지 탐색합니다. 기본 범위는 입력한 경로 자체와 하위 경로입니다. `/app/`을 입력하면 `/app/items`는 포함하지만 `/application`과 `/other`는 제외합니다. 서버 루트 URL을 입력하거나 **같은 서버 전체**를 선택하면 같은 스킴·호스트·포트의 다른 경로도 검사합니다. 쿼리는 최초 입력 경로에만 유지하고 다른 경로로 복제하지 않습니다. URL에 포함된 아이디·비밀번호와 `#` 화면 위치는 받지 않습니다. 상세 동작은 [URL 범위 안내](docs/URL_SCOPE.md)를 참고하세요.

연결·표면 탐색·설정 점검·접근 제어·경로 분석은 실제 진행 단계를 나타냅니다. 진단 중에만 표시하며 완료·실패·중단 후에는 숨깁니다.

헤더·디버그 정보·제한된 자격증명 응답·CORS·수집 키의 관리자 응답을 정해진 경로와 휴리스틱으로 검사합니다. 연계 경로는 관찰된 응답과 일치하는 아티팩트 값·세션을 연결한 추론입니다. 제공되는 차단점은 각 단계의 수정 후보입니다.

이 도구는 전체 URL 크롤러, 모든 OWASP 항목 검사기, 임의 사이트의 계정·소유권 정책을 자동 추론하는 도구, 최소 비용 방어 최적화 엔진이 아닙니다. 세션 간 권한 대조에는 명시한 계정과 보호 정책이 필요합니다. JSON은 자체 WVA 스키마이며 SARIF 형식이 아닙니다. 결과 0건이 전체 웹 보안의 안전을 의미하지 않습니다. 접근 권한이 있는 대상에서 사용하세요.
